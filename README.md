# Board

Небольшая доска задач в стиле Jira: React и Gravity UI на фронтенде, Go API с JSON-хранилищем на бэкенде.

## Что понадобится

- [Bun](https://bun.sh/) 1.4 или новее;
- [Go](https://go.dev/dl/) 1.27 или новее;
- Git — если проект был получен через GitHub.

Проверьте, что обе утилиты доступны из той же консоли, в которой будет запускаться проект:

```bash
bun -v
go version
```

В Git Bash Go иногда не попадает в `PATH`. Для текущей сессии добавьте его так:

```bash
export PATH="/c/Program Files/Go/bin:$PATH"
```

Чтобы сохранить настройку, добавьте эту строку в `~/.bashrc`, затем откройте новый Git Bash.

## Быстрый запуск

```bash
bun install
bun dev
```

Откройте [http://localhost:3000](http://localhost:3000). Фронтенд будет доступен на порту `3000`, а Go API — на `http://localhost:8080`.

Одна команда запускает оба процесса: Bun поднимает React-приложение, а Air запускает Go API и перезапускает его при изменении файлов `.go`, `.json` и `.yaml`.

## Проверка проекта

```bash
bun run check
bun run build
```

`check` запускает форматирование, линтеры, TypeScript-проверку и проверки Go API. `build` собирает production-версию фронтенда в `dist/`.

## Полезные команды

```bash
# Только фронтенд
bun run dev:frontend

# Только API с hot reload
bun run dev:api

# Пересобрать типы из OpenAPI-схемы
bun run api:generate
```

Не редактируйте вручную `server/api/api.gen.go` и `src/api/generated/schema.ts`: это сгенерированные файлы. Меняйте `api/openapi.yaml`, затем запускайте `bun run api:generate`.

## Данные и частые проблемы

Данные доски хранятся в `server/data/board.json`, поэтому действия в интерфейсе сохраняются между перезапусками API. Это демо-хранилище для локальной разработки.

Если в приложении появляется `Failed to fetch`, сначала убедитесь, что в терминале есть работающий процесс API и что открыт `http://localhost:8080/api/board`. Если Go был установлен после открытия терминала, перезапустите терминал, чтобы обновился `PATH`.
## Политика версий

Все прямые зависимости в `package.json` зафиксированы точными версиями: без диапазонов `^` и `~`. `bun.lock` обязательно хранится в репозитории и фиксирует всё транзитивное дерево зависимостей.

Обновляйте версии осознанно отдельным изменением: после обновления запускайте `bun run check` и `bun run build`, а затем коммитьте одновременно `package.json` и `bun.lock`.
## Git hooks

После клонирования и `bun install` автоматически устанавливается Lefthook. При необходимости установите хуки вручную:

```bash
bunx lefthook install
```

`pre-commit` обрабатывает только добавленные в индекс файлы: Biome и ESLint — для JavaScript/TypeScript, `gofmt` — для Go. Исправления форматтера автоматически добавляются обратно в staged-набор.

`pre-push` запускает полный `bun run check` и production-сборку. Поэтому в удалённый репозиторий не уйдёт код, который проходит проверку лишь на части файлов.
